# BetFlow: Blockchain Analytics and Web Scraping Pipeline for SatoshiDice Transactions

## Project Overview
BetFlow is an advanced data science and blockchain forensics pipeline designed to audit, reconstruct, and analyze transaction architectures generated by **SatoshiDice**, the historic high-volume on-chain betting platform. The system processes an extensive relational dataset compiled from the Bitcoin blockchain, tracking transaction dynamics from the Genesis Block (January 3, 2009) up to block height 214,562 (December 31, 2012).

The core objective is to trace the velocity of capital, model transaction dependency structures using graph theory, and employ browser automation to cluster and de-anonymize deterministic payment chains through external blockchain intelligence sources.


## Analytical Framework

The pipeline executes a multi-tiered analytical strategy divided into three core categories:

### 1. Macro and Micro Ledger Analytics
* **Temporal Traffic Density**: Computes the ratio of SatoshiDice betting transactions relative to global Bitcoin transaction volumes across explicit monthly intervals to map historical adoption curves.
* **Address Popularity and Volume Mapping**: Quantifies the popularity of specific vanity betting addresses (prefixed with `1dice`) based on two distinct vectors: total contract invocations (count of bets) and gross transaction volume (total BTC value).
* **Bet-to-Payout Lifecycle Auditing**: Traces the operational latency ("distance") between a user's bet transaction and the casino's automatic payout transaction. Payouts are systematically paired by identifying when the casino's response input directly consumes an Unspent Transaction Output (UTXO) created by the initial bet transaction.
* **Granular Behavioral Profiling**: Conducts deep-dive sub-analyses restricted strictly to the top three most active betting contracts, mapping:
  * Multi-scale temporal distribution profiles across hourly, daily, and weekly frequencies.
  * Bivariate statistical correlations between user-allocated transaction fees ($y$-axis) and gross bet amounts ($x$-axis) visualized via clean scatter plots.
  * Probability distributions of time-delta intervals between consecutive bets to detect programmatic scheduling or automated bot activity.

### 2. Graph-Theoretic Sequence Reconstruction
* **Primary Scope Restriction**: Evaluates transaction frequencies across the historical ledger to isolate the single most active SatoshiDice vanity contract address (`1dice*`). This unique identifier serves as the definitive administrative perimeter for all subsequent graph network modeling.
* **Simple Bet Filtering**: Restricts the network dataset strictly to "simple bets" matching the explicit protocol signature: transactions containing exactly one input and exactly two outputs (one output routing the bet amount to the primary `1dice*` target address, and one change output returning leftover funds to the user).
* **Directed Graph Construction ($G=(V, E)$)**: Initializes a NetworkX Directed Graph where **Nodes ($V$)** represent independent simple bet transaction units and **Edges ($E$)** establish sequential transaction dependencies. A directed edge $(v_i, v_j)$ is drawn if and only if the input of transaction $v_j$ directly consumes the change output originating from transaction $v_i$. Edges are dynamically tagged with the responsible Bitcoin change address string.

* **Graph Analytics Pipeline**:
  * **Session Reconstruction via Network Paths**: Analyzes the graph topology to group connected simple bets into distinct directed paths. Each path represents a linear, continuous betting session where a player kept rolling over their change output into the next bet.
  * **Path Depth Evaluation**: Computes the exact size and length distribution of these extracted sessions, calculating how many steps (measured in nodes or edges) each betting chain lasted.
  * **Behavioral Longevity & Persistence Visualization**: Generates analytical plots of the session length distribution. These charts are used to study player habits, examining behavioral persistence and seeing how long players typically kept betting before stopping.
* **Target Address Extraction for Forensic De-anonymization**: Isolates the top $h$ longest betting chains (maximal paths of maximum depth). The pipeline compiles the unique set of all connecting change addresses embedded within the edges of these top paths, exporting the collection to act as the automated input manifest for the subsequent web scraping and entity profiling phase.

### 3. Automated Entity De-anonymization
* **Heuristic Clustering Audits**: Targets the top $h$ maximum-length betting chains and extracts the collection of unique connecting change addresses labeling the edges of those specific paths.
* **Automated Browser Exploration**: Deploys a defensive, headless Selenium web scraping infrastructure to query WalletExplorer for each target address, extracting its associated multi-input heuristic cluster label (either explicit service names or raw numeric wallet identifiers).
* **Comprehensive Entity Evaluation**: Compiles a structured analytical reporting table tracking each maximum-length chain across the following mandatory parameters:
  * Unique Chain Identifier.
  * Chain Length (measured by node/edge count).
  * Total number of unique Bitcoin addresses involved in the path.
  * Count of distinct wallet clusters identified via scraping.
  * Concentration percentage of addresses belonging to the predominant wallet entity.
  * Structural identification tag of the main wallet entity (resolved service name or native WalletExplorer numeric cluster ID).

## Installation Guide

### Prerequisites

* **Python**: Version 3.10 or higher.
* **Google Chrome**: Required on the host machine for browser automation.

### 1. Environment Isolation

To ensure dependency isolation and prevent version conflicts with global Python libraries, initialize and activate a localized virtual environment:

**On macOS and Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

**On Windows (Command Prompt):**

```bash
python -m venv .venv
.venv\Scripts\activate.bat
```

### 2. Dependency Ingestion

Install the full suite of computational, network analysis, and browser automation packages via `pip`:

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

*Note: The system utilizes `webdriver-manager` within `src/scraper.py` to automatically provision, configure, and match the correct binary version of Chromedriver to your local Google Chrome installation, removing manual configuration steps.*

## Data Configuration

Due to ledger file sizing constraints, raw transactional CSV files are omitted from standard version control tracking. 

### 1. Dataset Retrieval
The complete dataset required to execute this analytics pipeline is hosted directly within the repository's distribution architecture. You can download the official source files by navigating to the **Releases** section of this GitHub repository (under the latest version tag).

### 2. File System Setup
Prior to executing the pipeline, initialize your local storage and place the uncompressed source files into their designated directory:

1. Create the internal data directory structure (if not already instantiated by cloning):
```bash
mkdir -p data/raw data/processed
```

2. Populate the `data/raw/` directory with the following downloaded assets:

* `transactions.csv`: Relational map of blocks, timestamps, transaction hashes, and miner fees.
* `inputs.csv`: Linkages mapping inputs back to their parent spending sources.
* `outputs.csv`: Transaction output values and target deterministic integer indexes.
* `mapping.csv`: Cryptographic address hashes mapped to unified internal integer keys (used to systematically isolate `1dice*` vanity strings via string prefix matching).
* `satoshidice_addresses.csv`: Registry containing betting address parameters, winning odds, and payout multipliers.

## Usage Workflow

The entire analytical pipeline is organized to run end-to-end within the production Jupyter Notebook environment, which synthesizes executable blocks with professional algorithmic documentation.

### Launching the Pipeline

Execute the following command from the root directory of the repository to start the interactive development server:

```bash
jupyter notebook notebook/BetFlow_SatoshiDice.ipynb
```

### Execution Pipeline Stages

When running the cells sequentially, the framework executes the following sequential workflows:

1. **Memory-Optimized Ingestion**: Imports data streams using specialized schema configurations, downcasting standard 64-bit numerical representations to compact types (`uint32`/`int64`) and applying categorical parsing to handle multi-gigabyte data footprints seamlessly on consumer-grade hardware (adhering to Lezione 8 guidelines).
2. **Exploratory Analytics**: Computes statistical aggregates, processes transaction densities, and outputs trend visualizations regarding macro betting behavior, vanity address popularity, and payout latencies.
3. **Network Mapping & Sequencing**: Instantiates the NetworkX graph structures restricted to the primary target contract, executes edge filtering rules based on UTXO change consumption, and isolates sequential betting paths.
4. **Targeted Headless Scraping**: Runs a headless instance of Chrome via Selenium, navigating WalletExplorer with explicit architectural guards to capture multi-input cluster entities without triggering rate limits.
5. **Entity Profiling Report**: Validates de-anonymized entity groupings across extracted chains and outputs the final evaluation matrix tracking entity fragmentation and user persistence.
